# Rigor review: README `## Results` and `## Limits` against `docs/results/`

Note 2026-11-13: the README was restructured; the Results and Limits text reviewed here moved verbatim to [results-detail.md](results-detail.md) (one change: Reproduce step 4, 512 → 517 passed). The new README summary sections were checked separately by an independent tester.

Rubric: ARA Rigor Reviewer (six dimensions D1–D6, severities critical/major/minor/suggestion). The repo has no ARA directory, so the dimensions were applied directly to the README claims, with `docs/results/` as the evidence.

**Scope of this review.** Claims: README `## Results` (all subsections, including the new "Injection-threshold sweep" subsection and the figure captions) and `## Limits`. Evidence: files under `docs/results/` plus the gitignored per-run results in `data/autoresearch/classifier/data/`. Classifier-bench rows (43, 44, 73, 75) were checked against the regenerated `docs/results/classifier-bench.json` with `generated_at` = `2026-11-13T06:01:19+00:00` (new format: `models` key, six corpora including the red-team corpus, deberta and keyword-heuristic rows only, no Prompt Guard rows). The earlier draft used the committed version `2026-11-12T16:29:36+00:00`; the five old corpora rows are identical in both, so rows 43/44 did not change. No claim was re-measured with Jev; test suites were not run.

Method. Every numeric claim was recomputed from the case-level `cases` arrays (not only from `summary`), using throwaway scripts under `data/autoresearch/rigor/` (deleted at the end). Conformal thresholds were recomputed twice: with an independent split-conformal quantile and with the project's `firewall-calibrate`. Case-level `reasons`, `policy_violations`, `jev_*` fields and the `agent/scenarios/external/*.json` files were read for the non-count claims.

Version used for classifier-bench claims: regenerated `docs/results/classifier-bench.json`, `generated_at` = `2026-11-13T06:01:19+00:00` (`models` = [protectai/deberta-v3-base-prompt-injection-v2]). Re-checked after regeneration: the metrics of the five old corpora (n_pos, n_neg, precision, recall, fpr, auroc, both backends) are identical to the earlier committed version (`2026-11-12T16:29:36+00:00`); only `p50_ms` may differ.

**Headline result: every sourced number matches; one claim wording (row 62, "allows no attack on any set") overstates the red-team result, which is a README fix, and no finding is critical. A handful of claims are unsourced inside `docs/results/` or in the repo, and several scope and design points are left "for Jim".**

**D2 Falsifiability: 3/5.** The README has pre-set, numeric acceptance criteria with a stated consequence ("a failed criterion would have reverted Jev v2"), which is above the norm. But it admits the criteria were set after an offline replay on the same sets, the margins are loose, and the Limits section does not state what result would refute the key claims (external 0 of 100, red-team 2 of 17). No claim carries an explicit refutation condition.

**D3 Scope calibration: 4/5.** Scope wording is careful: in-sample, rule-fitted, not independent, "not a rate for unseen attacks", re-score not a fresh run, hard caps are the guaranteed bound. Remaining over-reach risks: "ε = 1%" phrased as a bound while the threshold is the sample maximum; "These runs used 595 Jev calls" with no run list; derived rates from the lookalike benchmark that are conditional on reconstructable pairs.

**D4 Argument coherence: 4/5.** Claims in Results and Limits agree with each other and with ledger/jev-budget; the 7-vs-9-vs-6 red-team numbers are explained rather than contradicted; the classifier-only vs code-rules identity is explained by the data (external attacks trip no rule). **D5 Exploration integrity: 4/5.** The README plus ledger and jev-budget document aborted runs, corrected leaks in the external set before any Jev call, superseded numbers and the failed testnet status. No negative result is hidden. Not scored higher because the README itself (not the ledger) has no account of rejected design alternatives, and there is no tree of tried thresholds before 0.81.

**D6 Methodological rigor: 3/5 (unchanged).** Strengths: fixed criteria, held-out/in-sample labelling, calibration data stated, case-level artifacts committed, rerun commands given, and, new since the repeat run, a repeat of all three sets with real Jev on unchanged checker code, Wilson 95% intervals, agreement and score-stability statistics, and a recorded Jev model (`jev-1.14.0`) in both runs.
